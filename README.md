## 一、写在前面

很多用户购买机场服务后，体验不佳并非服务商的问题，而是使用方式不当。本手册将带你系统掌握机场使用的完整链路：订阅获取 → 客户端配置 → 规则分流 → 流量管理 → 性能优化 → 故障排查。

### 1.1 使用流程总览

```
购买套餐 → 获取订阅链接 → 客户端导入订阅 → 更新节点 → 选择节点
    → 开启代理 → 验证连通 → 日常使用 → 流量监控 → 到期续费
```

### 1.2 常见误区

- **误区一**：节点越多越好。实际上 90% 的用户日常只用 3-5 个节点，节点数量不如节点质量重要；
- **误区二**：全局代理更快。全局代理会让国内流量绕行海外，反而更慢更费流量；
- **误区三**：延迟越低越快。延迟只代表握手速度，实际下载速度取决于带宽与线路负载；
- **误区四**：不用管客户端更新。客户端内核迭代很快，旧版本可能不支持新协议，务必保持更新。

## 二、订阅的获取与格式

### 2.1 订阅链接的构成

订阅链接通常是这样的格式：

```
https://example.com/api/v1/client/subscribe?token=xxxxx
```

其中 `token` 参数是加密的账号标识，携带了你的套餐、流量、到期时间等信息。**切勿泄露该链接**。

### 2.2 常见订阅格式

| 格式 | 说明 | 适用客户端 |
|------|------|------------|
| SS 链接 | `ss://` 开头的 base64 编码 | Shadowsocks 系 |
| V2Ray 链接 | `vmess://` 或 `vless://` | V2Ray 系 |
| Trojan 链接 | `trojan://` | Trojan 系 |
| Clash 配置 | YAML 格式完整配置 | Clash 系 |
| Surge 配置 | 专用配置格式 | Surge / Stash |

### 2.3 订阅转换

当机场只提供通用订阅，而你的客户端需要特定格式时，可以使用转换工具：

```bash
# subconverter 本地部署示例（Docker）
docker run -d --name subconverter -p 25500:25500 tindy2013/subconverter:latest

# 转换示例：Clash 转 Surge
# https://localhost:25500/sub?target=surge&url=你的订阅链接
```

**注意事项**：

- 优先使用本地或自建转换服务，避免节点信息泄露给第三方；
- 转换后检查节点数量、名称是否完整；
- 定期重新转换（节点变更后旧转换结果会失效）。

## 三、客户端配置实操

### 3.1 Clash Verge Rev 完整配置流程

1. 从 GitHub Releases 下载并安装 Clash Verge Rev（注意认准 `Clash-Verge-Rev`，不要与旧版 `Clash-for-Windows` 混淆）；
2. 打开软件，进入"订阅"页面，点击"新建"；
3. 粘贴订阅链接，命名如"主力机场"，点击"保存"；
4. 点击订阅卡片上的刷新按钮，等待节点加载；
5. 进入"代理"页面，选择节点组与具体节点；
6. 打开"系统代理"开关，或开启 TUN 模式（推荐 TUN 模式，接管全部流量）；
7. 浏览器访问测试网站验证连通性。

### 3.2 Shadowrocket（iOS）配置流程

1. App Store 购买并安装 Shadowrocket（国区下架，需注册外区 Apple ID）；
2. 打开 App，右上角"+"号，选择"类型：Subscribe"；
3. 粘贴订阅链接，点击"保存"；
4. 点击订阅进入节点列表，选择节点；
5. 打开顶部开关，首次使用需允许添加 VPN 配置（按提示操作）；
6. 建议在"设置 → 订阅"中开启自动更新（如每天凌晨自动刷新）。

### 3.3 v2rayN（Windows）配置流程

1. 下载 v2rayN 与内核文件（v2ray-core / Xray-core，注意 CPU 架构对应 x64/arm64）；
2. 解压并启动 v2rayN，首次运行按提示选择内核路径；
3. 服务器 → 添加订阅 → 输入订阅地址 → 点击更新按钮；
4. 选择节点，右键设置为活动服务器；
5. 开启系统代理（建议 PAC 或全局按需）。

### 3.4 Clash Meta for Android 配置流程

1. 安装 Clash Meta for Android（或 Mihomo Party，GitHub 下载 APK）；
2. 配置 → 新建配置 → 从 URL 导入；
3. 粘贴订阅链接，保存并选择该配置；
4. 点击主界面开关，首次使用授予 VPN 权限；
5. 在"代理"中选择节点，建议开启"规则"模式。

### 3.5 路由模式详解

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 规则模式 | 按规则分流 | 日常使用（推荐） |
| 全局模式 | 所有流量走代理 | 需要固定出口 IP 时 |
| 直连模式 | 所有流量直连 | 排查问题时临时使用 |

- **规则模式**：按域名/IP 决定直连还是代理，国内网站直连、国外网站走代理。适合日常使用，推荐开启。
- **全局模式**：所有流量都走代理。适用场景：需要固定出口 IP（如某些网站按 IP 验证）、调试代理问题。日常使用不建议，会让国内网站变慢且浪费流量。
- **直连模式**：所有流量直连。适用场景：排查网络问题、临时关闭代理。

### 3.6 TUN 模式与系统代理的区别

| 对比 | 系统代理 | TUN 模式 |
|------|----------|----------|
| 原理 | 修改系统 HTTP 代理设置 | 创建虚拟网卡接管全部流量 |
| 适用范围 | 仅 HTTP/HTTPS 流量 | 所有 TCP/UDP 流量 |
| 游戏支持 | 不支持 | 支持 |
| DNS 泄漏 | 可能有 | 可控 |
| 性能损耗 | 极小 | 略高（通常感知不到） |

**结论**：日常浏览用系统代理即可；有游戏或 UDP 需求时开 TUN 模式。

## 四、规则与分流配置

### 4.1 为什么需要分流

分流（Split Routing）让国内流量直连、国外流量走代理，好处包括：降低延迟（国内访问无需绕行海外）、节省流量（国内流量不计入套餐配额）、提升稳定性（减少节点负载）、保护隐私（国内服务直接连接）。

### 4.2 常用分流规则写法

Clash 配置中规则从上到下匹配，先匹配的生效：

```yaml
rules:
  # 国内直连
  - GEOIP,CN,DIRECT
  - DOMAIN-SUFFIX,baidu.com,DIRECT
  - DOMAIN-SUFFIX,taobao.com,DIRECT
  # 流媒体走代理
  - DOMAIN-SUFFIX,youtube.com,PROXY
  - DOMAIN-SUFFIX,netflix.com,PROXY
  # 广告屏蔽
  - DOMAIN-KEYWORD,adservice,REJECT
  # 兜底规则
  - MATCH,PROXY
```

### 4.3 进阶分流策略

- **按设备分流**：手机/平板只代理必要应用，电脑全代理；
- **按应用分流**：仅浏览器走代理，其他应用直连；
- **按时间分流**：白天自动选低延迟节点，晚高峰切专线。

## 五、流量管理与计费

### 5.1 流量消耗大户

| 消耗源 | 1080P 估算 | 4K 估算 |
|--------|------------|---------|
| YouTube 视频 | 1.5 GB/小时 | 6 GB/小时 |
| Netflix 视频 | 1-3 GB/小时 | 7 GB/小时 |
| OS 系统更新 | 单次 2-8 GB | 同左 |
| 云盘同步 | 视文件量 | 同左 |
| P2P 下载 | 取决于任务 | 同左 |

### 5.2 省流量技巧

- 视频清晰度设置为自动或 1080P 以下；
- 关闭 App 后台自动播放与自动更新；
- 国内 App 流量设置为直连（规则分流天然实现）；
- 关注客户端实时流量统计，发现异常消耗及时排查；
- 使用客户端内置的"按应用代理"功能，仅让必要应用走代理。

### 5.3 计费规则确认

购买前务必确认以下五项，避免买到不适用的套餐：

1. **流量重置周期**：自然月（每月 1 号清零）vs 30 天滚动（购买日起算）。对月初购买的用户来说，自然月重置实际可用时间更短。
2. **超额处理方式**：限速（可用但慢）、停机（无法使用）、自动购买叠加包（扣费通知）。部分套餐超额后只降速不关机，对轻度超量用户更友好。
3. **设备数限制**：同时在线设备数，是按 IP 计还是按会话计。路由器代理只占 1 个设备数，但所有流量算一份。
4. **退款政策**：是否有退款窗口、申请流程如何。建议先月付验证后再购年付。
5. **升级规则**：从低套餐升级到高套餐是否支持补差价。

## 六、性能优化技巧

### 6.1 降低延迟

- 选择距离你物理位置近的节点（如国内用户优先香港、日本）；
- 使用专线节点（IEPL/IPLC）避开晚高峰拥堵；
- 开启客户端 TCP Fast Open（如内核支持）；
- 本地网络使用有线连接或 5GHz Wi-Fi。

### 6.2 提升带宽

- 选择带宽充裕的节点（参考机场测速公示）；
- 避免高峰期（20:00-24:00）的大流量任务；
- 下载任务分段进行，避免长时间占满单节点；
- 测试不同协议（如 Hysteria2 在丢包环境下带宽表现更好）。

### 6.3 客户端调优

```yaml
# Clash 性能相关配置
profile:
  store-selected: true        # 记住节点选择
  store-fake-ip: true         # 缓存 fake-ip
sniffer:
  enable: true                # 流量嗅探，提升分流准确性
tcp-concurrent: true          # 多路复用，提升多连接性能
```

## 七、故障排查速查表

| 症状 | 排查步骤 | 解决方法 |
|------|----------|----------|
| 全部节点连不上 | 检查账号是否到期/流量用完 | 续费或重置 |
| 单个节点连不上 | 切换其他节点测试 | 该节点故障，等恢复或换节点 |
| 能连但没网 | 检查系统代理是否开启 | 开启代理/TUN |
| 网页打不开 | 检查 DNS 设置 | 使用客户端内置 DNS |
| 速度极慢 | 换节点、换协议测试 | 专线节点或 Hysteria2 |
| 游戏频繁掉线 | 检查丢包率 | 游戏专线/有线网络 |
| 订阅更新失败 | 检查链接与网络 | 面板重新生成链接 |
| 提示设备超限 | 面板查看在线设备 | 踢除闲置设备 |
| DNS 解析错误 | 检查 DNS 泄漏 | 开启 DNS 保护 |
| 微信/QQ 异常 | 规则模式未生效 | 确认国内流量直连 |

### 排查黄金法则

1. **先换节点**：排除单节点故障；
2. **再换协议**：排除协议兼容问题；
3. **后查本地**：检查网络、防火墙、客户端设置；
4. **最后问客服**：提供节点名、时间、现象，让客服快速定位。

## 八、多设备协同方案

### 8.1 设备数限制下的分配策略

多数套餐限制 3-5 台设备，建议：主力设备（电脑、手机）常驻；次要设备（平板、电视）按需连接；路由器代理只保留一台，避免重复占用。

### 8.2 路由器方案（全屋代理）

```bash
# OpenWrt 安装 OpenClash 示例
opkg update
opkg install luci-app-openclash
# 配置：将机场订阅导入 OpenClash，开启自动更新
```

路由器代理的优点：全屋设备（含电视、游戏机）自动走代理；一次配置，永久生效；可在路由器层面做 DNS 优化。

### 8.3 家庭组网进阶

- 主路由 + 旁路由方案：旁路由负责代理，主路由保持稳定；
- 软路由（x86）性能更强，适合多设备高负载场景；
- 开启"仅代理国外流量"策略，国内设备访问不受影响。

### 8.4 家庭/团队共享方案

- **按设备分配**：将在线设备分配给固定成员，避免互相挤掉线；
- **错峰使用**：下载、更新等大流量任务安排到凌晨等低峰时段；
- **路由器集中代理**：家庭内所有设备共享一个路由器代理名额，大幅节省设备数；
- **团队订阅**：部分机场提供团队/多人套餐，价格优于单独购买多个套餐。

## 十、术语详解与资源库

### 10.1 核心术语详解

| 术语 | 全称 | 详解 |
|------|------|------|
| 订阅 | Subscription | 机场下发的节点配置链接，即用户与机场之间的桥梁 |
| 节点 | Node | 一台位于海外的代理服务器，是承载流量的实体 |
| 中转 | Transit/Relay | 国内入口转发至海外出口的组合线路，兼顾速度与隐蔽性 |
| 落地 | Exit | 流量最终离开节点去往目标网站的服务器位置 |
| IEPL | International Ethernet Private Line | 点对点物理专线，延迟低、丢包少、适合重度用户 |
| CN2 GIA | China Telecom 163 -> CN2 GIA | 电信高端线路，出国走精品网 |
| 解锁 | Unlock | 节点具备流媒体原生 IP，能正常访问 Netflix 等平台 |
| TUN | TUN Mode | 虚拟网卡模式，可接管全部 TCP/UDP 流量 |
| fake-ip | Fake IP | 客户端生成的虚拟 IP，用于加速分流和 DNS 预解析 |
| DNS 泄漏 | DNS Leak | DNS 查询绕过代理直连，导致隐私暴露 |
| 混淆 | Obfuscation | 将代理协议流量伪装成普通 HTTPS 流量，躲避审查 |
| 订阅转换 | Subscription Conversion | 将一种格式的订阅转换为另一种格式（如 Clash 转 Surge） |

### 10.2 协议选择指南

| 协议 | 特点 | 推荐场景 | 不推荐场景 |
|------|------|----------|------------|
| Shadowsocks | 轻量、成熟、老牌 | 入门、老设备 | 高审查环境 |
| VMess | 抗封锁能力中等 | 基础使用 | 高墙时期 |
| VLESS | 无加密开销、性能好 | 配合 XTLS/Reality | 单用 |
| Trojan | 伪装 HTTPS | 高墙环境、稳定性优先 | 低审查地区 |
| Hysteria2 | QUIC 协议、弱网友好 | 移动网络、晚高峰 | 已有专线 |
| WireGuard | 内核级 VPN | 自建、点对点 | 机场订阅 |

### 10.5 排障实战案例

**案例一：节点全部超时**
现象：所有节点都超时，但网络正常。
排查：1) ping 订阅域名，验证网络连通性；2) 检查是否被防火墙拦截；3) 换网络（4G/手机热点）测试。
结论：若换网络后正常，说明本地网络对订阅域名做了 DNS 劫持或 IP 封锁，可尝试用 DNS over HTTPS 或更换网络。

**案例二：YouTube 能打开但视频卡住**
现象：浏览器能打开 YouTube，但视频一直缓冲。
排查：1) 换节点测试（可能该节点带宽不足）；2) 检查是否开启了广告屏蔽（某些广告拦截器会干扰视频加载）；3) 测速验证节点带宽。
结论：多数情况下换节点即可解决，若所有节点都慢说明带宽不足或网络高峰期。

**案例三：iOS 无法连接**
现象：Shadowrocket 显示连接成功但 App 内无法联网。
排查：1) 确认在"设置 → VPN"中已开启该应用的 VPN 权限；2) 尝试重启客户端；3) 检查是否为 iOS 版本兼容问题（降级或升级 iOS）。
结论：iOS VPN 权限是常见问题，确认"允许 VPN"开关已打开。

### 10.6 客户端内核更新与版本管理

Clash Verge 使用的内核（Clash.Meta / Mihomo）会定期更新，包含新协议支持、Bug 修复与性能优化。保持内核更新可以：

- 支持最新协议（如 Hysteria2 新特性）；
- 修复已知崩溃和性能问题；
- 提升兼容性（macOS/Windows 系统更新后可能出现兼容性问题）。

**版本检查方法**：Clash Verge → 设置 → 关于 → 查看内核版本 → 对照 GitHub Releases 最新版本。

**更新建议**：不要追最新测试版（可能不稳定），选择 Releases 中标注为 Latest 的稳定版。

## 十一、常见问题 FAQ

**Q1：机场的流量和本地流量怎么区分？**
A：开启规则模式后，客户端会统计"代理流量"与"直连流量"，机场只计算代理流量。面板与客户端显示数值可能略有差异，以面板为准。

**Q2：为什么晚上 8 点后特别卡？**
A：晚高峰是所有跨境线路的拥堵期。可以尝试切换专线节点、改用 Hysteria2 协议，或将大流量任务改到凌晨执行。

**Q3：换手机后订阅还能用吗？**
A：可以。订阅链接绑定账号不绑定设备，在新设备导入即可。注意设备数限制，记得在面板踢掉旧设备。

**Q4：机场会记录我的浏览历史吗？**
A：取决于机场的日志策略。正规机场通常声明"不记录日志"或"仅保留必要运营日志"。在意隐私的话选择日志策略透明的服务商，敏感操作建议自建节点。

**Q5：可以同时在电脑和手机上用吗？**
A：只要不超过套餐设备数限制即可。建议电脑、手机各一台，路由器代理一台，刚好适配常见 3 设备套餐。

**Q6：订阅被墙了怎么办？**
A：部分机场提供备用订阅域名，或通过邮箱/工单获取。也可将订阅下载为本地文件导入客户端，但注意定期更新。

**Q7：如何判断节点是否被封锁？**
A：单个节点长时间连接超时、延迟测试全部失败，而其他节点正常，说明该节点 IP 可能被封锁，等待机场更换 IP 或切换备用节点即可。

**Q8：套餐到期后流量会清零吗？**
A：多数机场到期后流量清零、订阅失效，续费后重新计算。部分机场支持流量结转，购买前确认规则。

**Q9：可以跨区使用吗（人在海外用回国节点）？**
A：可以，反向使用同样成立。人在海外时选择国内中转节点即可访问国内平台，注意回国线路通常单独计费或限量。

**Q10：机场跑路怎么维权？**
A：选择支持月付的机场、避免一次性购买过长套餐是最好防线。已购买的年付套餐可尝试联系支付渠道申诉，但成功率有限，所以务必从小额月付开始。

**Q11：订阅链接每次打开都不一样，正常吗？**
A：正常。部分机场出于安全考虑，每次请求返回的订阅内容包含不同的 token 或加密参数，但导入到客户端后效果完全相同。

**Q12：为什么客户端显示节点在线但实际无法连接？**
A：这通常是因为节点 IP 被封锁，但客户端的延迟测试只测 TCP 握手成功不代表实际流量能通过。遇到这种情况换一个节点，或等待机场更换节点 IP。

**Q13：机场和自建节点可以同时用吗？**
A：可以。常见做法是机场为主力、自建为备用。在客户端中设置两个订阅，按优先级排序，自建节点排在最后兜底。
